# Terminus v0.1 — Terminal Core (Epic E0) — Design Spec

> Status: approved 2026-06-22. Scope: Epic E0 only. North-star: `VISION.md`.

## 1. Goal

Ship a **real, cross-platform terminal** that proves the Tauri + xterm.js +
PTY stack works on Windows, macOS, and Linux. This de-risks the hardest part of
the whole project before any panes/AI/media are layered on.

Success = open Terminus, get a working shell that runs `vim`, `htop`, `ssh`,
git with color; open tabs; split panes; pick a theme; edit a config file and
see it apply.

## 2. In scope (v0.1)

- PTY-backed terminal via `portable-pty` (ConPTY on Windows, forkpty on unix).
- xterm.js rendering with addons: **WebGL** (renderer), **fit**, **search**,
  **web-links** (OSC 8 / URL detection), **unicode11**, **clipboard**.
- True color, ligatures.
- **Tabs** and **splits** (binary split-tree: horizontal + vertical).
- **Theming** from JSON (reuse `res/themes/default.json` format) — applied to
  both xterm and the surrounding UI via CSS variables.
- **TOML config** (`config.toml`): appearance (theme, font, font size), shell
  (program, args, cwd), keybindings. Hot-reload on file change.
- **OSC 7 cwd tracking**: tab/pane title shows current dir; new split inherits
  the focused pane's cwd.
- Keybindings: new/close tab, next/prev tab, split H/V, focus pane, copy/paste,
  find. Defaults overridable in config.
- Cross-platform CI (GitHub Actions matrix: windows / macos / ubuntu).

## 3. Out of scope (later epics)

Command blocks (E1), detach/attach + persistence (E2), AI (E3), media/browser
panes (E4–E6), command palette / SSH manager / quake (E7), Lua / plugins (E8).
v0.1 has a static default keybinding scheme; no scripting.

## 4. Architecture

Two halves over Tauri IPC. Raw bytes end-to-end; **Rust never parses VT escapes**
— xterm.js owns all terminal interpretation. Clean boundary.

```
┌─────────────── Web frontend (TS) ───────────────┐
│  layout/   tabs + split-tree, focus, visibility  │
│  terminal/ wraps one xterm.js per pane           │
│  theme/    JSON theme → xterm theme + CSS vars    │
│  config/   fetch config, apply, react to reload  │
│  keys/     keybinding map → actions              │
└──────────▲───────────────────────│───────────────┘
   events   │ terminal://output/{id}│ commands
            │ terminal://exit/{id}  ▼ create/write/resize/close/get_config
┌──────────│───────────────────────▼───────────────┐
│  commands.rs   Tauri IPC surface (only entry pt)  │
│  session/      HashMap<TermId, PtySession>        │
│  pty/          spawn · reader thread · write · resize │
│  config/       load + watch TOML (serde + notify)  │
└──────────────── Rust core (src-tauri) ────────────┘
```

### 4.1 Backend units (Rust)

- **`pty`** — `PtySession`: one per terminal. Owns the `portable-pty` master,
  a child process, a dedicated **reader thread** that pumps bytes to the
  frontend via a channel, a writer, and `resize(cols, rows)`. Knows nothing
  about UI or tabs. Public API: `spawn(shell, args, cwd, size) -> PtySession`,
  `write(bytes)`, `resize(cols, rows)`, `id()`. Emits: output chunks, exit.
- **`session`** — `SessionManager`: `HashMap<TermId, PtySession>`. Create,
  look up, close, list. Owns id allocation. The only thing commands talk to.
- **`config`** — serde structs (`Config`, `Appearance`, `Shell`, `Keybindings`)
  + loader (find path per-OS via `dirs`), defaults, and a `notify` watcher that
  re-emits config on file change.
- **`commands.rs`** — Tauri command handlers, the sole IPC surface (see §5).
  Thin: validate, delegate to `session`/`config`, return `Result`.

### 4.2 Frontend units (TS, plain + Vite — no framework in v0.1)

- **`terminal`** — wraps one `Terminal` (xterm.js) + addons; subscribes to its
  `output`/`exit` events; forwards `onData`/resize to backend.
- **`layout`** — tab bar + recursive split-tree (`Leaf(TermId) | Split(dir,
  ratio, a, b)`); tracks focused leaf and visible set; handles split/close/
  resize/focus.
- **`theme`** — load JSON theme, map to `ITheme` for xterm + set CSS custom
  properties for chrome.
- **`config`** — `get_config` on boot, apply; re-apply on reload event.
- **`keys`** — map key combos → actions, dispatch to `layout`/`terminal`.

## 5. IPC contract

**Commands (frontend → Rust):**
- `create_terminal({ shell?, args?, cwd?, cols, rows }) -> { id }`
- `write_stdin({ id, data })`
- `resize({ id, cols, rows })`
- `close_terminal({ id })`
- `get_config() -> Config`

**Events (Rust → frontend):**
- `terminal://output/{id}` — payload: bytes (base64 or `Vec<u8>`).
- `terminal://exit/{id}` — payload: `{ code }`.
- `config://reloaded` — payload: `Config`.

## 6. Data flow

- **Input:** keypress → xterm `onData(data)` → `write_stdin(id, data)` →
  `PtySession.write` → shell.
- **Output:** shell stdout → pty reader thread → channel → `emit
  terminal://output/{id}` → xterm `.write(bytes)`.
- **Resize:** pane resize → fit addon computes cols/rows → `resize(id, c, r)`
  → `PtySession.resize`.
- **Spawn split:** read focused pane cwd (from OSC 7 state) → `create_terminal`
  with that cwd → add `Leaf` to split-tree.
- **Exit:** pty EOF / child exit → `emit terminal://exit/{id}` → pane shows
  `[process exited <code>]`, stays closable; reader thread ends.

## 7. Error handling

- Shell spawn fails → `create_terminal` returns `Err` → UI shows inline pane
  error, no crash.
- PTY read EOF / child exit → `terminal://exit` → `[process exited]`, closable.
- Write to dead pty → swallowed, session marked exited (no panic).
- Config parse error → fall back to built-in defaults + non-blocking warning;
  never block startup.
- Command handlers: `Result` across every IPC boundary; **no `unwrap`** in
  handlers or the reader thread.

## 8. Testing

- **Rust unit:** TOML parse + defaults + bad-input fallback; `PtySession`
  spawns `echo hello` and reader yields `hello`; `resize` doesn't panic;
  `SessionManager` create/close lifecycle.
- **Frontend unit:** split-tree ops (split/close/focus/ratio), theme→xterm/CSS
  mapping, keybinding resolution.
- **Integration:** spawn real default shell, `write_stdin "echo terminus\n"`,
  assert an `output` event contains `terminus`.
- **CI:** GitHub Actions matrix windows + macos + ubuntu → build + test. This
  is the contract that keeps cross-platform-day-1 honest.

  src/{ main.rs, commands.rs, pty/mod.rs, session/mod.rs, config/mod.rs }
  Cargo.toml  tauri.conf.json  build.rs

  main.ts  index.html

`temp.txt`) stays in-tree for now, **deleted in a later step**. Git history
preserves it regardless. New Rust/TS lands in `src-tauri/` + `src/` and won't
collide with the C++ headers during the transition.
