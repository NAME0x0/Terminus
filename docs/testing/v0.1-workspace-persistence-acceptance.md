# v0.1 Workspace Persistence Acceptance

This is the packaged-native acceptance gate for the v0.1 Persistent Project
Workspaces product loop. It is separate from the E0 terminal compatibility
suite in [`terminal-compatibility-smoke.md`](terminal-compatibility-smoke.md).

## Windows packaged pass — 2026-07-21

Environment:

- Windows x64 (build 10.0.26200.8894) with the system WebView2 runtime;
- release executable produced by `npm run build` (`tauri build --no-bundle`);
- disposable workspace/config root supplied through `TERMINUS_CONFIG_DIR`;
- disposable project directories under the ignored Tauri target directory;
- WebView2 remote debugging used only for accessibility and screenshot evidence.

| Journey boundary | Result | Evidence |
|---|---:|---|
| First launch | Pass | The isolated store opened with zero workspaces, no terminal, a disabled New tab action, and create-workspace guidance. |
| Create | Pass | Creating `Alpha Project` against a real local directory launched a live default-shell PTY in that project. |
| Arrange | Pass | The initial terminal moved to `api`; split-right created `web`; split-down created `ops`; all three sessions remained live in the expected mixed-direction layout. |
| Persist | Pass | `workspaces.json` used schema version 1 and preserved stable tab/pane IDs, split directions and ratios, focused pane identity, and the three distinct working directories. |
| Close | Pass | A native Windows close request flushed state, removed the window, terminated the application process, and returned exit code 0. |
| Restore | Pass | Reopening the release executable restored the same three-pane geometry using replacement PTYs. Running `cd` in every pane reported the persisted `api`, `web`, and `ops` directories. |
| Switch | Pass | A new `Beta Workspace` opened independently; switching to Alpha restored three panes, and switching back restored Beta's single pane. |
| Rename | Pass | `Beta Workspace` became `Beta Renamed` in the sidebar and persisted JSON without changing its project root or layout. |
| Remove | Pass | Removing Beta returned to Alpha and removed only Beta's saved workspace state. The beta project directory remained on disk. |
| Clear | Pass | Settings warned that project files would remain, then cleared every saved workspace. The app returned to first-run with an empty schema-valid store and both fixture project directories intact. |
| Runtime health | Pass | No packaged frontend errors were reported at the end of the journey. |

Local visual evidence is retained in the ignored
`src-tauri/target/acceptance-v01/` directory. It includes first-run, three-pane,
restored-directory, and cleared-state captures; generated test data is not
committed.

## Defects closed during the pass

1. Native test isolation did not follow the overridden Windows `APPDATA`
   location. `TERMINUS_CONFIG_DIR` now provides one explicit root for both
   `config.toml` and `workspaces.json`, with the existing platform location as
   the default.
2. The default Windows `cmd.exe` did not emit OSC 7, so pane metadata retained
   a stale directory after `cd`. Terminus now augments the cmd prompt with an
   invisible OSC 7 sequence while preserving the user's visible prompt.
3. Destroying the only webview after a successful flush left a headless Tauri
   process alive. The close path now flushes first and then explicitly exits the
   application event loop.
4. Clear-state confirmation now remains above Settings until cancel or
   completion; a successful clear closes Settings and returns to first-run.
